# Фаза 0 — окружение и выбор геометрического ядра

Этот документ для тех, кто знает базовый Rust, но не сталкивался с CAD-ядрами. Он объясняет,
что было сделано в Фазе 0, какие понятия нужны, чтобы читать код, и почему решения приняты именно так.
Первоисточники: `docs/adr/0001-geometry-kernel.md`, `docs/adr/0002-dependency-licenses.md`,
`docs/environment.md`.

## Что сделано

- Подготовили машину разработки (Windows 11, rustc 1.99.0, CMake 4.4.3, FreeCAD 1.1.4,
  cargo-deny 0.20.2, Ollama 0.40.4) и записали версии в `docs/environment.md`.
- Написали общий набор из 5 тестовых деталей с аналитическими эталонами:
  `spikes/common/expect.rs`.
- Сделали три spike-программы для кандидатов: `spikes/kernel-truck`, `spikes/kernel-fornjot`,
  `spikes/kernel-occt`. Каждая строит те же 5 деталей и сверяет объём и габариты.
- Написали `tools/freecad_check.py`: он открывает STEP-файлы во FreeCAD и печатает валидность,
  число тел, объём и bbox. Это независимая проверка экспорта.
- Приняли решение (ADR 0001): ядро — OpenCascade (OCCT 7.8) за трейтом `Kernel`.
- Приняли политику лицензий (ADR 0002): только permissive-лицензии, LGPL — исключение
  лишь для `occt-sys`.
- Создали крейт `kernel` (трейт `Kernel`, `Shape`, `Profile`, `Mesh`) и крейт `occt` —
  собственную C++/Rust-обвязку над OCCT, где любая ошибка ядра становится `Err`, а не падением процесса.
- Написали golden-тесты ядра и тесты «враждебного» ввода (`crates/occt/src/tests.rs`,
  `crates/occt/tests/step.rs`).

## Ключевые понятия

**B-rep (boundary representation)** — способ хранить твёрдое тело через его границу. Тело не
«набор точек внутри», а список поверхностей, которые его ограничивают:

- **вершина** (vertex) — точка;
- **ребро** (edge) — кривая между вершинами (отрезок, дуга окружности);
- **грань** (face) — кусок поверхности (плоскость, цилиндр, сфера), ограниченный рёбрами;
- **оболочка** (shell) — набор граней, склеенных по рёбрам в замкнутую поверхность;
- **тело** (solid) — оболочка вместе с пониманием «что внутри».

Куб: 8 вершин, 12 рёбер, 6 граней, 1 оболочка, 1 тело. В тесте
`box_with_hole_by_extrude` пластина с отверстием имеет 7 граней: 6 от коробки и 1 цилиндрическая
стенка отверстия.

**Геометрическое ядро** — библиотека, которая умеет строить и менять B-rep: выдавливать,
вращать, пересекать тела, скруглять. Писать его с нуля — годы работы, поэтому берут готовое.
FormCraft — это интерфейс, история построения и параметры поверх ядра.

**Булевы операции** — объединение (`Union`), вычитание (`Cut`) и пересечение (`Intersect`)
тел. Вычитание цилиндра из бруска даёт отверстие. Это одна из самых сложных операций для ядра:
надо найти все линии пересечения поверхностей и пересобрать грани.

**Скругление (fillet)** — замена острого ребра поверхностью дуги заданного радиуса. На углах,
где сходятся три скруглённых ребра, ядро строит сферические куски. Поэтому в эталоне
`fillet_all` в объёме есть слагаемое шара `4/3·π·r³`, а граней у тела становится 26.

**Shell / thick solid** — «выдолбить» тело: удалить выбранные грани и оставить стенку
заданной толщины. Так делают коробки и корпуса. Ядро смещает грани внутрь на толщину и
собирает новое тело. Если стенка толще самого тела, получается мусор, а не ошибка, поэтому
результат нужно проверять отдельно (см. ниже).

**Тесселяция** — превращение гладких поверхностей в треугольники для отрисовки. Параметр
`deflection` — максимальное отклонение треугольников от настоящей поверхности в мм.

Почему объём по треугольникам ≈ точный объём. Для замкнутой сетки с наружными нормалями
объём считается по теореме о дивергенции: для каждого треугольника `(a, b, c)` берём
тетраэдр с вершинами в начале координат и в `a`, `b`, `c`. Его знаковый объём равен
`a · (b × c) / 6`. Сумма по всем треугольникам даёт объём тела: тетраэдры, «смотрящие» наружу,
прибавляются, остальные вычитаются, и всё лишнее сокращается. Это ровно код
`Mesh::volume` в `crates/kernel/src/mesh.rs`. Для плоских граней сетка точна; для
цилиндров и сфер ошибка зависит от `deflection` и уменьшается вместе с ним. Тест
`tessellation_matches_brep` сравнивает сеточный объём с точным из OCCT с допуском `1e-3`.

**STEP** (ISO 10303) — стандартный файловый формат обмена B-rep между CAD-системами. Если STEP из
нашего кода без ошибок открывается во FreeCAD и объём совпал, экспорт корректен.

**Golden-тест** — тест, который сравнивает результат с заранее известным правильным ответом
(«золотым»). У нас ответы аналитические: объём коробки с отверстием `60·40·10 − π·25·10`
считается формулой, а не берётся из прошлого запуска.

## Как выбирали ядро

Кандидатов три:

1. **truck** (чистый Rust, truck 0.6 / shapeops 0.4);
2. **Fornjot** (чистый Rust, 0.49);
3. **OpenCascade** (C++, OCCT 7.8.1, через opencascade-rs 0.3).

Пять тестовых деталей и эталонные объёмы (`spikes/common/expect.rs`, ADR 0001):

| Тест | Деталь | Эталонный объём, мм³ |
|---|---|---|
| box_hole | 60×40×10, сквозное Ø10 | 23 214.60 |
| fillet_all | куб 20, все 12 рёбер R2 | 7 804.70 |
| cyl_cut | 40×40×20 минус цилиндр Ø20 | 25 716.81 |
| revolve | прямоугольник r 10..20, h 30, 360° | 28 274.33 |
| shell | 40×30×20, верх удалён, стенка 2 внутрь | 7 152.00 |

Объём считается по триангуляции, допуск 1 %; bbox — допуск 0.05 мм.

Критерии по порядку важности:

1. тестовый набор проходит;
2. STEP открывается во FreeCAD без ошибок;
3. при прочих равных — чистый Rust (tie-breaker).

Итоги из таблицы ADR:

- **truck**: 3 из 5. Нет скругления всех рёбер (`fillet_all`) и нет thick solid (`shell`). STEP
  с ошибками ридера в 4 файлах из 4; у `box_hole` в STEP 32 «Unresolved Reference».
- **Fornjot**: 0 из 5 по API: нет булевых операций, нет скруглений, нет STEP-экспорта.
- **OCCT**: 5 из 5, STEP во FreeCAD без ошибок в 5 файлах из 5, объёмы точные
  (например, `box_hole` 23 214.60).

Критерий 3 (чистый Rust) работает только при равенстве по 1–2, а равенства не было. Поэтому
выбран OCCT. Чтобы не привязываться к нему навсегда, всё спрятано за трейтом `Kernel`:
когда у truck появятся скругления и shell, можно добавить второе ядро.

Лицензия OCCT — LGPL-2.1 с исключением OCCT. ADR 0002 разрешает LGPL только для крейта `occt-sys`
(он лишь собирает исходники OCCT); для остальных зависимостей она запрещена в `deny.toml`.

## Почему своя обвязка над OpenCascade

Готовый opencascade-rs годился для spike, но не для продукта. Найденные проблемы:

**1. Аварийное завершение процесса.** OCCT сообщает об ошибках исключениями C++
(`Standard_Failure`, `StdFail_NotDone`). В Rust такое исключение нельзя перехватить: процесс
завершается с сообщением «Rust cannot catch foreign exceptions, aborting». Воспроизведение:
контур с повторённой первой точкой, то есть ребро нулевой длины, в `Wire::from_ordered_points`.
Значит, неверный ввод пользователя мог бы убить всё приложение, а это нарушает правило
never-crash.

**2. Как мы это лечим.** В `crates/occt/cpp/bridge.cxx` каждая функция-обёртка выполняется внутри
макроса `FC_GUARD(op, ...)`. Он ловит `Standard_Failure`, `std::exception` и всё остальное
(`catch (...)`) и бросает `std::runtime_error` с именем операции. Библиотека `cxx` превращает
такое исключение в `Err` на стороне Rust, потому что функции объявлены как `Result`.
Макрос variadic (`...` и `__VA_ARGS__`) не случайно: тело внутри `try { }` содержит запятые
(аргументы вызовов, списки инициализации), а препроцессор C++ считает запятую разделителем
аргументов макроса. С обычным вторым параметром тело развалилось бы на несколько аргументов.

**3. Глобальный мьютекс.** В `crates/occt/src/lib.rs` есть `KERNEL_LOCK`, и каждая операция берёт
его (`let _g = lock();`). OCCT не рассчитан на параллельное использование общей топологии:
построение сетки пишет триангуляцию прямо в разделяемые объекты формы. Поэтому потоки идут по
очереди. Тест `parallel_use_is_serialised` запускает 4 потока. Отравленный мьютекс (паника в другом
потоке) работу не блокирует: `unwrap_or_else(|poisoned| poisoned.into_inner())`.

**4. Проверка результата.** «OCCT сказал, что готово» не значит «результат верный». Функция
`checked` в `lib.rs` после скругления, фаски и shell проверяет, что тело валидно (`is_valid`) и
имеет положительный объём. Для shell она ещё проверяет, что объём не вырос по сравнению с
исходным. Затем `shell` сравнивает bbox до и после: внутренняя оболочка не должна менять
наружные габариты и обязана уменьшить объём. Если стенка слишком толстая, OCCT может вернуть
«успешный» мусор, и такой результат отклоняется ошибкой «wall thickness too large for this body».
Тест `hostile_inputs_are_errors_not_aborts` проверяет, что `K.shell(&b, &[0], 20.0)` для куба 10
даёт ошибку, а не странное тело.

Ещё одно следствие своей обвязки: патч заголовков OCCT под MSVC не нужен, потому что мы
используем `opencascade::handle<T>` напрямую, без `Handle_X`.

## Трейт Kernel

`Kernel` (`crates/kernel/src/lib.rs`) — список операций, которые нужны CAD-фичам: примитивы,
`extrude`, `revolve`, `boolean`, `fillet`, `chamfer`, `shell`, запросы `faces`/`edges`/`mass_props`,
`tessellate`, STEP и сериализация. Остальной код знает только этот трейт. Каждая операция
возвращает `Result` и не должна паниковать (в крейтах включён `deny(clippy::unwrap_used, ...)`).

`Shape` — непрозрачный: внутри `Arc<dyn Any + Send + Sync>`. Зачем: слой выше не должен знать,
что внутри лежит `TopoDS_Shape` из OCCT. Каждое ядро кладёт туда свой тип и достаёт его через
`downcast_ref`; чужую форму оно отвергает ошибкой `ForeignShape`. `Arc` делает клон дешёвым,
а формы неизменяемы: операции возвращают новые формы.

Грани и рёбра адресуются индексом в порядке обхода топологии **для данной формы**. Индексы
нестабильны: после пересборки модели с другим параметром та же грань может получить другой номер.
Поэтому в следующих фазах слой регенерации (regen) будет хранить семантические селекторы
(«верхняя грань», «рёбра этой грани») и каждый раз заново переводить их в индексы.

Пример в стиле `plate_with_hole` из `crates/occt/src/tests.rs`:

```rust
let p = Profile::new(Plane::XY, Loop2::rect(DVec2::ZERO, DVec2::new(60.0, 40.0)))
    .with_hole(Loop2::circle(DVec2::new(30.0, 20.0), 5.0));
let plate = Occt.extrude(&p, DVec3::Z * 10.0)?;   // пластина 60x40, толщина 10, отверстие Ø10
let m = Occt.mass_props(&plate)?;                  // m.volume == 60*40*10 - PI*25*10
let mesh = Occt.tessellate(&plate, 0.01)?;         // треугольники для отрисовки
```

## Особенности окружения

- **Кириллица в пути.** Репозиторий лежит в папке с русскими буквами. Сборка OpenCascade
  через CMake с этим справляется (обычный `target/`), а вот FreeCADCmd, `ollama create` и
  bat-файлы `cmd.exe` — нет: для них файлы копируются во временную ASCII-папку (`C:\fc-target`,
  `C:\fc-models`).
  Сама обвязка при этом юникод понимает: тест `round_trip_in_unicode_dir` пишет и читает файл
  `деталь.step` в папке `formcraft тест ...`.
- **CMake 4** отказывается собирать исходники OCCT из-за старого `cmake_minimum_required`.
  Лечение — `CMAKE_POLICY_VERSION_MINIMUM = "3.5"` в разделе `[env]` файла `.cargo/config.toml`.
- **Первая сборка OCCT долгая** (в ADR: десятки минут). Дальше она берётся из кэша `target/`;
  в CI этот каталог тоже нужно кэшировать.
- **STEP-тесты с `harness = false`.** После любой передачи STEP бинарник libtest падает с access
  violation уже при выходе из процесса, хотя все тесты прошли. Обычные программы (приложение,
  CLI) завершаются нормально. Поэтому `crates/occt/tests/step.rs` — самостоятельная программа
  с собственным `main`: она сама печатает `test ... ok` и возвращает `ExitCode`.
- **`ollama pull` не работает.** Сетевой прокси работает в режиме fake-IP: адрес CDN реестра
  попадает в диапазон 198.18.0.0/15, и Ollama отказывается идти по редиректу на «непубличный»
  адрес. Обход: скачать GGUF-файл с Hugging Face через `curl` и создать модель командой
  `ollama create ... -f models/qwen2.5-coder-7b.Modelfile` (точные команды — в
  `docs/environment.md`).

## Проверь себя

1. Почему исключение C++ из OCCT нельзя просто «поймать» в Rust и что делает `FC_GUARD`?
2. Почему макрос `FC_GUARD` объявлен с `...`, а не с обычным параметром для тела?
3. Почему нельзя сохранить в файле проекта «скруглено ребро номер 5»?
4. Почему сумма `a · (b × c) / 6` по треугольникам даёт объём тела?

<details>
<summary>Ответы</summary>

1. Rust не умеет обрабатывать чужие (C++) исключения: при попытке пройти через границу FFI
   процесс аварийно завершается («Rust cannot catch foreign exceptions, aborting»). `FC_GUARD`
   ловит исключение на стороне C++ и бросает `std::runtime_error`, который `cxx` превращает в `Err`.
2. Тело содержит запятые, а препроцессор делит аргументы макроса по запятым. `__VA_ARGS__`
   собирает всё обратно в один фрагмент кода.
3. Индексы граней и рёбер действительны только для конкретной формы и не стабильны между
   пересборками. Нужен семантический селектор, который слой regen каждый раз переводит в индексы.
4. Каждый член суммы — знаковый объём тетраэдра из начала координат и вершин треугольника.
   Для замкнутой сетки с наружными нормалями вклады вне тела сокращаются, остаётся объём тела.

</details>
