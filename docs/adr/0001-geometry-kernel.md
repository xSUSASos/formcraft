# ADR 0001 — B-rep ядро

- Статус: принято
- Дата: 2026-10-15

## Контекст

FormCraft — параметрический твердотельный CAD. Нужны: выдавливание, вырез, вращение, скругления
и фаски рёбер, отверстия, оболочка (shell), булевы операции, экспорт/импорт STEP. План (п. 5,
Фаза 0) требует сравнить `truck`, `opencascade-rs` (OCCT) и Fornjot на одном тестовом наборе.

Критерии: (1) тестовый набор проходит, (2) STEP открывается во FreeCAD без ошибок, (3) при прочих
равных — чистый Rust.

## Тестовый набор

`spikes/common/expect.rs` — аналитические эталоны, объём считается по триангуляции (допуск 1 %),
bbox — допуск 0.05 мм. STEP проверяется `tools/freecad_check.py` (FreeCAD 1.1.4, `freecadcmd`):
валидность, число тел, объём, bbox, ошибки ридера.

| Тест | Деталь | Эталонный объём, мм³ |
|---|---|---|
| box_hole | 60×40×10, сквозное Ø10 | 23 214.60 |
| fillet_all | куб 20, все 12 рёбер R2 | 7 804.70 |
| cyl_cut | 40×40×20 минус цилиндр Ø20 | 25 716.81 |
| revolve | прямоугольник r 10..20, h 30, 360° | 28 274.33 |
| shell | 40×30×20, верх удалён, стенка 2 внутрь | 7 152.00 |

### Найденные проблемы OCCT-обвязки

1. **Аварийное завершение процесса.** Любое исключение C++ из OCCT (`Standard_Failure`,
   `StdFail_NotDone`) в opencascade-rs проходит через `cxx` без перехвата → «Rust cannot catch
   foreign exceptions, aborting». Воспроизведено: контур с повторённой первой точкой (ребро нулевой
   длины) в `Wire::from_ordered_points`. Пользовательский ввод может уронить приложение — это
   нарушает правило never-crash. Плюс в opencascade-rs много `unwrap/expect`.
2. **MSVC:** на `_MSC_VER >= 1800` OCCT объявляет `Handle_X` классом-наследником, а мост
   opencascade-sys ожидает typedef → ошибки C2440. Обход в spike — патч `Standard_Handle.hxx`.
3. **CMake 4:** нужен `CMAKE_POLICY_VERSION_MINIMUM=3.5`. **Компоновка:** нужен `advapi32`.
4. Первая сборка OCCT — десятки минут; нужен кэш в CI.

## Решение

**Ядро — OpenCascade (OCCT 7.8)**, за трейтом `Kernel` в крейте `kernel` (остальной код про OCCT
не знает; можно добавить второе ядро, например truck, когда в нём появятся скругления и shell).

Обвязку **пишем свою** — крейт `occt` (cxx-мост, C++-обёртки в `crates/occt/cpp/`):
- каждая функция-обёртка ловит `Standard_Failure` и `std::exception` и возвращает ошибку
  (`cxx`-функции объявлены как `Result`), проверяет `IsDone()` до `Shape()`; аварий нет;
- используем `opencascade::handle<T>` напрямую, без `Handle_X` → патч OCCT не нужен;
- сборку самой библиотеки OCCT берём из `occt-sys` (LGPL-2.1, только сборка исходников OCCT);
- набор функций — ровно то, что нужно фичам (примитивы, призма, вращение, булевы, скругление,
  фаска, отверстие, thick solid, триангуляция, топология, свойства масс, STEP/STL).

Код opencascade-rs не копируем (свою обвязку пишем по документации OCCT).

## Последствия

- Лицензия: OCCT — LGPL-2.1 с исключением OCCT; статическая компоновка допустима, потому что
  FormCraft открыт (MIT OR Apache-2.0) и пользователь может пересобрать его с другой версией OCCT.
  В `deny.toml` LGPL разрешена **только** для `occt-sys`; записано в NOTICE.
- Слои: L0 `kernel` (трейт и типы) ← `occt` (реализация). Выше `kernel` никто не видит C++.
- CI: кэшировать `target/` (сборка OCCT), `CMAKE_POLICY_VERSION_MINIMUM` в `.cargo/config.toml`.
- Чистый Rust (критерий 3) уступает критериям 1–2: truck не умеет скругления, shell и чистый STEP.
