# ADR 0003 — Plugin API v1

- Статус: принято (дизайн); реализация — Фаза 6
- Дата: 2026-10-16

## Контекст

PLAN §3А: два вида расширений. **Скрипты** — внешние программы через JSON control channel
(тонкий Python-клиент `formcraft`). **Плагины (Add-Ins)** — WebAssembly-компоненты в песочнице:
свои команды, кнопки, диалоги, панели, свои фичи на таймлайне, события, доступ к модели.
Требования: плагин не роняет приложение, лимиты памяти и времени, разрешения в манифесте,
семвер API, несовместимый плагин не загружается с понятным сообщением.

Что уже есть к Фазе 4:
- реестр команд в рантайме (`engine::registry`): `CommandSpec` с JSON-схемой, `source`,
  регистрация/снятие по источнику — UI, S-box, MCP, CLI и ИИ читают его, списков в коде нет;
- control channel `formcraft --control PORT` (`{id, method, params}` → `{id, result|error}`) —
  тот же протокол, что у MCP Remote;
- фичи хранят параметры как JSON с выражениями и перестраиваются в `regen`.

## Решение

### Скрипты
Протокол control channel из Фазы 4 и есть API скриптов: `engine.execute`, `engine.commands`,
`model.inspect`, `selectors.list`, `ui.render`, `ui.screenshot`, `ui.click`, `ui.state`.
Python-пакет `formcraft` (чистый Python, stdlib only) — обёртка: `fc = formcraft.connect(port)`,
`fc.execute("solid.box", size=[10, 20, 5])`, `fc.inspect()`, `fc.export(path)`. Для запуска без
окна — `formcraft-cli script file.py` поднимает headless-сессию с тем же каналом на свободном
порту и передаёт его в `FORMCRAFT_PORT`. Python в приложение не встраивается.

### Плагины
- **Рантайм:** `wasmtime` (Apache-2.0) с component model; интерфейс — WIT
  `crates/plugin-api/wit/formcraft.wit`, пакет `formcraft:plugin@1.0.0`.
- **Граница — JSON + ресурсы.** Параметры и результаты команд идут JSON-строками и проверяются
  хостом по схеме команды (одна валидация для всех входов). Геометрия — ресурс `solid`,
  которым владеет хост; плагин получает только хэндлы, все операции ядра идут через тот же
  `Kernel` с проверками (ошибка → `err`, не падение).
- **Экспорт плагина:** `init` (регистрация команд, фич, панелей), `run-command`,
  `regenerate(kind, params) -> solid` для custom features, `panel`, `on-event`.
- **Импорт:** `host.execute` (любая команда реестра — модель меняется только командами, undo
  работает как обычно), `inspect`, `selection`, `log`, файлы по разрешениям; `geometry.*`.
- **Регистрация:** id команд и фич обязаны начинаться с id плагина (`gear.*`); `source` =
  `plugin:<id>`; при выгрузке хост снимает всё с этим источником. Схемы команд плагина сразу
  попадают в S-box, MCP `list_commands` и промпт ИИ — потому что все они читают реестр.
- **Custom feature:** `FeatureKind::Custom { plugin, kind, params }`. При regen хост вызывает
  `regenerate` и применяет `body-op` (new/join/cut/intersect) как у родных фич. Последнее
  успешное тело сериализуется (BREP) в документ; если плагина нет или он упал — фича строится
  из этого замороженного тела и получает предупреждение на таймлайне.
- **Диалоги:** декларативно из JSON-схемы параметров (как родной Feature dialog из Фазы 3:
  числа с выражениями, выбор грани/ребра/тела через `format: "face"|"edge"|"body"`, чекбокс,
  список `enum`). Своего UI-кода в плагине нет — ему не нужен egui.
- **Манифест `plugin.toml`:** `id`, `name`, `version`, `author`, `license`, `api = "1.0"`,
  `wasm = "gear.wasm"`, `[permissions] files = ["~/Documents/gears"]`, `network = false`.
  По умолчанию — только модель и UI; файлы/сеть подтверждает пользователь при установке.
- **Изоляция:** отдельный `Store` на плагин; лимит памяти (`ResourceLimiter`, 256 МиБ по
  умолчанию); время — epoch interruption (тик 10 мс, дедлайн 2 с на вызов, 10 с на `init`).
  Trap/таймаут → плагин выгружается, его команды снимаются, ошибка в логе и в статусе;
  приложение продолжает работать.
- **Версии:** `api` в манифесте сравнивается по семверу с `formcraft-plugin-api`; мажор не
  совпал → не загружаем, сообщение «плагин для API X, приложение поддерживает Y».
- **Где лежат:** `<config>/plugins/<id>/`, `<config>/scripts/`; установка из `.zip` (проверка
  путей, без `..`), диалог Scripts and Add-Ins (Shift+S).

## Рассмотренные варианты

- **Нативные dll/so** — нет: нестабильный ABI Rust, нет песочницы, падение роняет процесс.
- **Встроенный Python (PyO3) / Lua** — нет песочницы с лимитами, тяжёлая сборка, вторая
  экосистема; для разовых задач скриптов через control channel достаточно.
- **wasm без component model (сырой ABI + JSON в памяти)** — проще хост, но ручное управление
  памятью и нет типизированных ресурсов для геометрии; WIT даёт генерацию биндингов для
  Rust/C/Go/JS.
- **Плагин рисует UI сам** — нет: плагину пришлось бы зависеть от egui, ломались бы темы и
  раскладка; декларативные диалоги из схемы уже есть.
- **Custom feature как «макрос из команд»** (плагин возвращает список команд) — проще, но
  плодит фичи на таймлайне и не даёт процедурной геометрии (эвольвента шестерни). Оставлено
  как запасной путь: плагин может и так, через `host.execute`.

## Последствия

- Фаза 6 добавляет `FeatureKind::Custom`, хост `crates/plugin` (wasmtime), WIT-биндинги в
  `crates/plugin-api`, `formcraft-cli plugin new`, Python-пакет и пример «Шестерня».
- Протокол control channel становится публичным API скриптов — менять только совместимо.
- wasmtime увеличивает размер бинарника (~10–15 МБ); лицензия Apache-2.0 проходит `cargo deny`.
