# Архитектура FormCraft

## Слои (проверяет `cargo xtask layers`)

Крейт зависит только от крейтов **строго нижнего** слоя. Ниже L7 никто не знает про egui/eframe/rfd.

| Слой | Крейты | Роль |
|---|---|---|
| L0 | `kernel`, `plugin-api` | трейт `Kernel`, `Shape`, `Profile`, `Mesh`; типы Plugin API |
| L1 | `occt`, `sketch` | реализация ядра на OpenCascade (своя cxx-обвязка); эскизы и решатель |
| L2 | `doc` | документ: фичи, таймлайн, параметры, выражения, undo |
| L3 | `regen`, `tess` | перестроение таймлайна в тела; тесселяция |
| L4 | `io` | STEP/STL/3MF/.fcraft |
| L5 | `engine` | сессия, **реестр команд** (JSON-схемы, регистрация в рантайме), выбор, undo |
| L6 | `ai`, `plugin`, `render` | ИИ-конвейер; хост WebAssembly-плагинов; рендер wgpu |
| L7 | `ui-egui`, `mcp` | интерфейс в стиле Fusion; MCP-сервер |
| L8 | `formcraft`, `formcraft-cli` | приложения |

## Ядро

`formcraft_kernel::Kernel` — объектно-безопасный трейт (`&dyn Kernel`), фигуры — непрозрачные
`Shape` (Arc), заглянуть внутрь может только своё ядро. Грани/рёбра адресуются индексами в
топологии конкретной фигуры; индексы не стабильны между перестроениями — `regen` каждый раз
разрешает семантические селекторы (`top`, `+X`, `vertical_edges`, …) и сигнатуры в индексы.

`formcraft_occt::Occt`: C++-фасад `crates/occt/cpp/bridge.cxx`, каждая функция внутри
`FC_GUARD` (исключение OCCT → `std::runtime_error` → `Err` в Rust). Все вызовы OCCT
сериализуются глобальным мьютексом (OCCT пишет триангуляцию в общую топологию даже через const).

## Команды

Каждое действие пользователя — команда в реестре `engine` с id, подписью, местом в toolbar,
горячей клавишей и JSON-схемой параметров. Реестр заполняется в рантайме (встроенные команды
регистрируются при старте, плагины — при загрузке), поэтому UI, S-поиск, ИИ (схема в промпте),
MCP, CLI и скрипты видят один и тот же набор.
