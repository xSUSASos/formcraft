# FormCraft — план разработки

> Параметрический 3D-CAD с интерфейсом в стиле Fusion 360 и **локальным ИИ**, встроенным в рабочий процесс.
> Чистый Rust, egui, MCP, CLI, по конвенциям Crafting Apps (ArtCraft, образец — `storytold/cadcraft`).
> Файл кладётся в корень репозитория как `PLAN.md`.

---

## 0. Правила для Claude Code

1. Фазы выполняются строго по порядку. Следующая фаза начинается только после выполнения критериев приёмки текущей.
2. Один шаг — один коммит, после каждого шага `cargo xtask ci` зелёный.
3. **Режим обучения.** После каждой фазы пиши `docs/learn/phase-N.md` для новичка: что сделано, почему так, ключевые понятия, куда смотреть в коде.
4. Решения не ждут человека: пиши ADR в `docs/adr/NNNN-*.md` и продолжай работу.
5. **Clean-room.** Повторяем раскладку и логику работы Fusion 360, но не копируем код, иконки, тексты и ресурсы Autodesk. Все иконки рисуются заново, в коде.
6. Бренд ArtCraft (`docs/brand/`) не используем. Проект называется FormCraft и живёт в отдельном репозитории.
7. **Делегирование.** Простую работу отдавай Sonnet через скилл делегирования (см. п. 7).

## 1. Цель и границы MVP

**Главная фишка:** «кронштейн 60×40×5, два отверстия M6, скругления R3» → локальная LLM строит **параметрическую историю** (обычные фичи на таймлайне), которую потом можно править руками. Работает офлайн, без аккаунта.

**Входит в MVP:** эскизы с размерами и ограничениями; extrude, cut, revolve, fillet, chamfer, hole, shell, булевы операции; таймлайн и параметры; интерфейс в стиле Fusion (п. 2); встроенный ИИ (п. 3); плагины и скрипты как во Fusion (п. 3А); STEP/STL/3MF; MCP и CLI.

**Не входит:** сборки и кинематика, чертежи, CAM, МКЭ, поверхности, листовой металл, облако, web-версия с ИИ.

## 2. Интерфейс в стиле Fusion 360

Раскладка повторяет логику Fusion, чтобы пользователь Fusion сразу ориентировался. Реализация на egui, внешний вид собственный: тёмная и светлая темы, свои иконки.

**Источник правды по внешнему виду — [`UI_SPEC.md`](UI_SPEC.md)** (цвета, размеры, типографика, иконки, вид каждой зоны, приёмка внешнего вида). Здесь — только раскладка по зонам.

| Зона | Где | Что делает |
|---|---|---|
| **Application bar** | верх | файл, сохранение, undo/redo, имя документа |
| **Toolbar** | под ним | переключатель рабочей среды (MVP: Design), вкладки **Solid / Sketch / Inspect / Tools**, группы Create / Modify / Construct / Inspect с выпадающими списками |
| **Browser** | слева | дерево: Document Settings, Named Views, Origin (плоскости и оси), Sketches, Bodies; глаз видимости, переименование, контекстное меню |
| **Canvas** | центр | 3D-вьюпорт: орбита, пан, зум, подсветка при наведении, выбор граней, рёбер и тел |
| **ViewCube** | правый верхний угол | кликабельный куб: грани, рёбра, углы, Home |
| **Navigation bar** | низ по центру | orbit, pan, zoom, fit, визуальные стили (shaded, shaded+edges, wireframe), сетка |
| **Timeline** | самый низ | история фич иконками: перетаскивание для смены порядка, маркер отката, двойной клик открывает редактирование, подсветка ошибок |
| **Feature dialog** | справа, плавающий | параметры активной операции, поля принимают выражения (`L*2`), кнопки OK/Cancel, живое превью |
| **Манипуляторы** | на canvas | стрелки и кольца у превью: тянешь стрелку — меняется расстояние выдавливания или радиус |
| **Marking menu** | правый клик | радиальное меню частых команд и список ниже |
| **Shortcut box (S)** | клавиша S | поиск команды по названию; сюда же встроен ИИ (п. 3) |
| **Sketch palette** | справа в режиме эскиза | ограничения, сетка, «смотреть на эскиз», Finish Sketch |
| **Text commands** | сворачиваемая панель внизу | лог и консоль команд (как командная строка CADCraft) |
| **Scripts and Add-Ins** | вкладка Tools, Shift+S | список скриптов и плагинов: запуск, остановка, «загружать при старте», создать новый из шаблона, открыть папку, показать лог плагина |

**Горячие клавиши в духе Fusion:** S (поиск), E (extrude), L (line), R (rectangle), C (circle), D (dimension), F (fillet), H (hole), Q (press pull), M (move), Shift+средняя кнопка (orbit) и др. Таблица в `docs/shortcuts.md`, всё переназначается.

Все панели перемещаются, сворачиваются и сбрасываются (как в CADCraft).

## 3. ИИ, встроенный в рабочий процесс

**Допущение:** ИИ — не отдельный чат сбоку, а часть инструментов, как у Fusion. Всё, что он делает, становится обычными фичами на таймлайне.

### 3.1 Точки входа

| Где | Как работает |
|---|---|
| **Shortcut box (S)** | Нет точного совпадения с командой → строка «✦ Сделать с ИИ: …». Enter запускает генерацию |
| **Вкладка Solid → Create → «Generate»** | Диалог: текстовое описание, единицы, опции «новое тело / к выбранному», превью, OK |
| **Правый клик по грани/телу/фиче → «Изменить с ИИ…»** | Выбранное передаётся в контекст: «сделай здесь 4 отверстия M5 по углам с отступом 8» |
| **Правый клик по фиче на таймлайне → «Объяснить»** | Человеческое описание фичи и её параметров |
| **Панель Assistant** (сворачиваемая, справа) | История запросов, уточнения, статус модели и VRAM |

### 3.2 Поведение

- Результат показывается как **превью** (полупрозрачно) + список предлагаемых фич. «Принять» — фичи ложатся на таймлайн **группой** (как группа в Fusion), её можно развернуть и редактировать. «Отклонить» — ничего не меняется.
- Вся операция ИИ — **один шаг undo**.
- Параметры, придуманные ИИ, попадают в таблицу параметров с понятными именами (`plate_length`, `hole_d`).
- Статус в UI: «Генерация… / Исправление (2/3)… / Готово / Ошибка: …», кнопка отмены.

### 3.3 Устройство

- LLM выдаёт **JSON-список фич** по строгой схеме, без кода. Схема и system prompt генерируются автоматически из реестра команд, чтобы не расходиться с кодом.
- Грани и рёбра задаются семантическими селекторами (`top`, `+X`, `vertical_edges`, `circular_edges`, `largest_planar_face`…) и ссылками на выбор пользователя.
- Конвейер: промпт → LLM (structured output) → валидация схемы → regen → при ошибке отчёт обратно в LLM (до 3 попыток) → превью.
- Бэкенды за трейтом `LlmBackend`: Ollama (по умолчанию `127.0.0.1:11434`), OpenAI-совместимый (llama.cpp, LM Studio), Mock для тестов. Облако — только явно включается в настройках.
- Модель по умолчанию выбирается по `ai-bench` из кандидатов под объём VRAM.
- Логи запросов и ответов пишутся в `logs/ai/` для будущего дообучения.

## 3А. Плагины и скрипты (как Scripts / Add-Ins во Fusion)

Опора та же, что у всего приложения: **каждое действие — команда с JSON-схемой**. Плагины пользуются тем же реестром команд, что UI, ИИ и MCP.

### Два вида расширений

| Вид | Аналог во Fusion | Как устроен | Для чего |
|---|---|---|---|
| **Скрипт** | Script | Внешняя программа на любом языке, работает через JSON control channel. Официальный тонкий клиент — Python-пакет `formcraft` (`pip install formcraft`), без встраивания Python в приложение | Разовые задачи: сгенерировать 50 шестерён по таблице, пакетный экспорт, отчёт |
| **Плагин (Add-In)** | Add-In | WebAssembly-компонент (`wasmtime`, Apache-2.0), API описан в WIT. Писать можно на Rust, C/C++, Go, AssemblyScript и др. Загружается при старте, работает в песочнице | Постоянные расширения: свои команды, кнопки, панели, свои фичи |

Нативные `.dll/.so`-плагины не делаем: у Rust нестабильный ABI, нет песочницы, падение плагина роняет приложение.

### Что умеет плагин (Plugin API v1)

- **Команды:** регистрирует свою команду с JSON-схемой параметров. Она сразу доступна из UI, S-поиска, MCP, CLI и **ИИ** — схема автоматически попадает в промпт.
- **UI:** кнопка на toolbar (вкладка, группа, иконка в SVG), пункт marking menu и контекстного меню, **диалог команды** в стиле Feature dialog (декларативно: числовое поле с выражениями, выбор грани/ребра/тела, чекбокс, список), своя сворачиваемая панель.
- **Свои фичи (custom features):** фича плагина встаёт на таймлайн как родная, хранит параметры, перестраивается при regen (например, «шестерня», «резьба по ГОСТ», «рёбра жёсткости»). Если плагин удалён — фича сохраняет последнее тело как замороженное и помечается предупреждением.
- **События:** документ открыт/сохранён, выбор изменился, regen завершён, команда выполнена.
- **Доступ к модели:** чтение дерева, параметров, геометрии (bbox, объём, грани), создание фич через команды.

### Безопасность и формат

- Плагин = папка с `plugin.toml` (имя, версия, автор, лицензия, версия API, **разрешения**) + `.wasm` + ресурсы.
- Разрешения по умолчанию: только модель и UI. Файловая система (только выбранные папки) и сеть — по запросу в манифесте, пользователь подтверждает при установке.
- Лимиты памяти и времени выполнения, падение или зависание плагина не роняют приложение — плагин выгружается, ошибка в логе.
- Папки: `<config>/plugins/` и `<config>/scripts/`; установка из `.zip` или по ссылке на Git-репозиторий. Магазин плагинов — после релиза.
- Версионирование API: `formcraft-plugin-api` (крейт + WIT), семвер, несовместимый плагин не загружается с понятным сообщением.

### Комплект для разработчика

- Шаблоны: `formcraft-cli plugin new --lang rust|python-script`.
- Документация `docs/plugins/` + 3 примера: «Шестерня» (custom feature + диалог), «Пакетный экспорт STL» (скрипт на Python), «Масса по таблице материалов» (панель + события).
- ИИ может сгенерировать заготовку плагина по описанию — опционально, после релиза.

## 4. Архитектура

```
kernel   ┐  обёртка над B-rep ядром (за трейтом)
sketch   ┤  2D-эскизы + решатель ограничений
doc      ┤  документ: фичи, таймлайн, параметры, выражения, undo (copy-on-write)
regen    ┤  перестроение таймлайна → B-rep, кэш, ошибки по фичам
tess     ┤  тесселяция для рендера и STL
io       ┤  STEP / STL / 3MF / .fcraft (zip: JSON + превью)
engine   ┤  сессия, команды (каждое действие = команда с JSON-схемой), выбор, undo
ai       ┤  LlmBackend, промпты из реестра команд, валидация, цикл исправления
plugin   ┤  хост WebAssembly (wasmtime), WIT API, манифесты, разрешения, custom features
plugin-api  отдельный публикуемый крейт + WIT для авторов плагинов
render   ┤  wgpu: тела, рёбра, превью, манипуляторы, подсветка
ui-egui  ┤  интерфейс Fusion-style (п. 2)
mcp      ┘  MCP-сервер поверх engine
apps: formcraft · formcraft-cli
```

`cargo xtask ci`: fmt, clippy, тесты, проверка слоёв (ниже `ui-egui` никто не знает про egui), `cargo deny` (лицензии).

## 5. Фазы

### Фаза 0 — Окружение и выбор ядра
- Установить зависимости (см. стартовый промпт), записать версии в `docs/environment.md`.
- Spike: `truck`, `opencascade-rs` (OCCT), Fornjot. Тестовый набор: коробка с отверстием, скругление всех рёбер, вырез цилиндром, revolve, shell, экспорт STEP → открыть во FreeCAD.
- Критерии выбора: (1) тестовый набор проходит, (2) STEP открывается без ошибок, (3) при прочих равных — чистый Rust.
- **Приёмка:** ADR 0001 с таблицей «прошёл/не прошёл»; ядро за трейтом.

### Фаза 1 — Каркас и оболочка интерфейса
- Workspace, крейты-заглушки, `xtask ci`, GitHub Actions (Windows и Linux).
- Вся раскладка из п. 2 пустыми панелями: application bar, toolbar с вкладками, browser, canvas с сеткой, ViewCube, navigation bar, timeline, свернутая text commands. Темы и сохранение раскладки.
- **Приёмка:** окно открывается, панели двигаются и сбрасываются, орбита/пан/зум и ViewCube работают; скриншоты в `docs/images/`.

### Фаза 2 — Тело на экране
- Примитивы, булевы, тесселяция, рендер с рёбрами, выбор и подсветка граней/рёбер/тел.
- Экспорт STEP/STL. Тела появляются в Browser.
- **Приёмка:** `formcraft-cli run ... --save out.step` → FreeCAD открывает файл с верными размерами (тест сверяет объём и bbox).

### Фаза 3 — Эскиз, фичи, таймлайн
- Режим эскиза: линия, прямоугольник, окружность, дуга; размеры (D), ограничения, sketch palette, Finish Sketch.
- Фичи: extrude/cut (E), revolve, fillet (F), chamfer, hole (H), shell, press pull (Q).
- Feature dialog с выражениями и **манипуляторами**, живое превью.
- Таймлайн: редактирование, перестановка, маркер отката, подсветка ошибок. Таблица параметров. Undo/redo. Формат `.fcraft`.
- Marking menu, shortcut box (S) пока без ИИ, горячие клавиши.
- **Приёмка:** собрать кронштейн мышью как во Fusion, изменить параметр → корректное перестроение; golden-тесты на 10 эталонных деталей.

### Фаза 4 — Команды, CLI, MCP
- Каждая операция = команда с JSON-схемой. `formcraft-cli`: info, convert, run, render, commands, mcp.
- MCP: `execute`, `inspect_model`, `render` (PNG), `list_selectors`, `screenshot`, `ui_click`.
- Подключить FormCraft MCP к самому Claude Code для самопроверки.
- Реестр команд проектируется расширяемым (команды и фичи регистрируются в рантайме), чтобы потом в него встали плагины. Написать ADR «Plugin API v1» (WIT-интерфейс), пока без реализации.
- **Приёмка:** Claude Code через MCP строит кронштейн и проверяет его через `inspect_model` и `render`.

### Фаза 5 — Встроенный ИИ ⭐
- Крейт `ai`: бэкенды, промпты из реестра, структурный вывод, цикл исправления.
- Все точки входа из п. 3.1, поведение из п. 3.2.
- 20+ few-shot примеров типовых деталей (пластина, втулка, фланец, кронштейн, корпус с крышкой, вал со шпонкой…).
- `cargo xtask ai-bench`: 50 промптов с эталонами (bbox, объём, число отверстий) → % валидных / перестроенных / совпавших. Прогон на 2–3 моделях-кандидатах, выбор модели по умолчанию — ADR.
- **Приёмка:** офлайн, 12 ГБ VRAM: «фланец Ø100, 4 отверстия Ø9 на Ø80, толщина 10» → корректная группа фич на таймлайне меньше чем за 60 с; ai-bench ≥70% валидных тел на простых деталях.

### Фаза 6 — Плагины и скрипты
- Крейты `plugin` и `plugin-api`: хост wasmtime, WIT API v1 из ADR, манифест, разрешения, лимиты, изоляция падений.
- Скрипты через JSON control channel + Python-пакет `formcraft`.
- Диалог Scripts and Add-Ins (Shift+S), автозагрузка, лог плагина.
- Custom features на таймлайне, плагиновые кнопки, диалоги и панели.
- Команды плагинов автоматически попадают в S-поиск, MCP и схему ИИ.
- Шаблоны `plugin new`, документация `docs/plugins/`, 3 примера из п. 3А.
- **Приёмка:** плагин «Шестерня» устанавливается из zip, добавляет кнопку и диалог, фича на таймлайне перестраивается при смене параметра; ИИ по запросу «шестерня z=20 m=2» вызывает команду плагина; Python-скрипт экспортирует все тела в STL; плагин с бесконечным циклом выгружается по таймауту без падения приложения.

### Фаза 7 — Шлифовка и релиз
- Inspect: измерение, сечение, свойства тела (масса по плотности).
- Импорт STEP как базового тела. 3MF. Настройки, логи, локализация RU/EN.
- Сборки: Windows (msi/portable), Linux (AppImage). README: сборка, установка Ollama и модели.

### Фаза 8 — Опционально, после релиза
Магазин плагинов, генерация плагинов ИИ, mesh-генерация (сайдкар на Python, TRELLIS.2 — MIT; лицензию Hunyuan3D проверить), фото/эскиз → деталь через vision-LLM, дообучение модели на логах, компоненты и сопряжения, чертежи с экспортом DXF в CADCraft.

## 6. Тестирование

- Юнит-тесты по крейтам; golden-тесты геометрии (объём, площадь, bbox, число граней).
- STEP туда-обратно: экспорт → импорт → те же величины.

- ИИ: тесты на Mock-бэкенде в CI, реальный ai-bench — отдельная команда (нужен GPU).

## 7. Делегирование (Opus ↔ Sonnet)

**Остаётся у основной модели:** архитектура, ADR, ядро и regen, топологическое именование, решатель эскизов, конвейер ИИ, манипуляторы, Plugin API (WIT), хост wasmtime и песочница, custom features, проверка приёмки, ревью кода от Sonnet.

**Отдаётся Sonnet через скилл делегирования:** шаблонные тесты и golden-фикстуры, `docs/learn/` по готовому конспекту, README и прочая документация, локализация строк, иконки по ТЗ, простые панели и диалоги по готовой спецификации, few-shot примеры по образцу, переименования, мелкие фиксы clippy, Python-пакет `formcraft` по готовому протоколу, примеры плагинов и `docs/plugins/` по готовому API.

Правило: задача для Sonnet должна быть самодостаточной (входы, ожидаемый результат, критерий проверки). Результат Sonnet всегда проверяется: `cargo xtask ci` + быстрый просмотр диффа основной моделью.

## 8. Риски

| Риск | Решение |
|---|---|
| Слабые скругления/булевы ядра | Фаза 0 + ядро за трейтом |
| Топологическое именование ломает историю | Семантические селекторы + сигнатуры, golden-тесты |
